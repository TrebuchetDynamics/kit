# Planning skills for current Autowork

## Scope and decisions

Use the native `tasks/` store through Docs Sync and `autowork tasks`, not a second
queue or restored TODO/goals ledger. Current shared contracts own planning behavior;
completed implementation batches, test reports and integration timelines live in
Git history. Current goal statuses and unfinished acceptance remain independent.

Keep Plan For Me decisive within delegated scope and Plan With Me interactive for
consequential unresolved intent. Preserve public names, aliases, literal arguments,
privacy, origin routing, authority, review/checks and owner stops. Bare autonomous
discovery must not become a missing-goal interview. No new registry, schema, receipt
format, mandatory experiment or acceptance ceremony is introduced.

## Task-store and check contract

- Manual closure uses `autowork tasks done ID --by WHO --reason TEXT [--evidence REF]`.
  It creates no coordinator-verification receipt. Ordinary dependencies, verified
  dependencies and goal qualification remain distinct. Never manufacture a waiver
  or manually close implementation acceptance merely to unblock a queue.
- Allocate plain numbered task IDs without hash suffixes through `autowork tasks`.
  Preserve existing identities and references; never renumber live work or promise
  cross-checkout collision freedom.
- Use literal JSON for prose and carry a material earlier read's `record_revision`
  into supported `--expect` updates. On refusal reread and reapply only attributable
  changes, never blind-retry a stale full snapshot. Operation-local locking alone
  does not protect the earlier read.
- Hot production files, cold overlap and test files have distinct scheduler effects.
  Shared paths alone are not logical dependencies. Use actual cohesion, conflict cost
  and testability, not a blanket large-file extraction requirement.
- Prefer existing public test seams and the worker's focused per-behavior test budget.
  An instruction-contract guard is itself a behavior seam, not proof of agent adherence.
  Preserve task-required checks, affected landing qualification and main's separate
  full gate without repeatedly running whole suites for a focused prose correction.
- `tasks why` proves committed-store selection eligibility/order, not capacity,
  ownership admission or dispatch. Named-slice reconciliation belongs to the current
  coordinator, not a fabricated per-goal-frontier CLI guarantee.

## Decision-complete Plan For Me

Every ready task must contain the consequential choices required to execute without
another design interview. This is not a guarantee against unknown failures or
unavailable external inputs. Choose evidence-supported engineering trade-offs within
delegated scope; Plan With Me retains consequential intent interviews.

Classify each material builder finding as already answered, planner-resolvable,
worker-reversible or genuinely owner/external-blocked. Resolve the first two into
the saved contract, leave reversible implementation details to the worker, and scope
real missing-input holds to affected work. Nothing material remains unclassified in
a ready task. Metadata validity alone is not readiness. Missing local fixtures or
setup that the task may implement are deliverables, not invented external blockers.

Use the shared closure procedure in `RESEARCH-PLAN.md`, `PLANNING-CRAFT.md` and
`PLAN-HANDOFF.md` from native/portable entrypoints and discovery. Preserve full-batch
persistence, clear-task lightweight handling, task reuse, genuine gates and all
standalone/no-write/coordinator limits. Known failed operations return their existing
task/attempt/candidate/source evidence to the same authorized coordinator for supported
recovery; do not manufacture new product decisions or duplicate tasks. Runtime failure
alone is not permission to split acceptance or erase the original obligation.

## Task writing quality

Status: Accepted scope from the owner's request that skills create better task
names and descriptions. The choices below are planner calls within that request.
This extends the existing naming policy; it does not repeat its completed
implementation or rename the current backlog.

Use one shared quality standard in `skills/shared/TODO-WORKCENTER.md`, reached
through the existing planning and handoff links. It applies when Plan For Me,
Plan With Me, Docs Sync, Autoresearch or Autowork discovery creates or materially
refines a task. Other task-producing skills use the same work-center contract.
Do not copy the standard into every adapter or add a task-store schema field.

- Keep the existing concrete action/outcome plus affected-object naming rule.
  Read title and short independently and beside sibling tasks. Short stays within
  40 characters without truncating away the distinguishing outcome.
- Make `scope` explain the intended behavior change and its bounded context, not
  just a path list or a restatement of the title. Include the reason when it helps
  distinguish the work. Keep known constraints and exclusions explicit.
- Give the implementer a concrete first action, source-backed decisions and the
  required inputs. Keep observable acceptance separate from exact check commands.
  Mark future tests unrun. Identify genuine missing inputs without inventing
  requirements or repeating an already settled permission question.
- Use existing fields and brief notes only where they add information. Do not
  repeat the same procedure across scope, acceptance and multiple body notes.
  Link shared workflow rules instead of pasting them into every task. Retain all
  mandatory checks and real limitations; brevity must not remove obligations.
- Before saving, read the task as an implementer: can they identify the outcome,
  boundary, starting action and evidence of success without another design round?
  Repair wording from source evidence; unresolved intent stays explicit. Do not
  rewrite an active contract, manufacture readiness or bulk-edit unrelated tasks.

Extend the existing instruction-contract tests for shared routing and add bounded
cases to the existing planning specimens. Cover vague names, sibling tasks with
similar titles, a path-only description, a long repetitive description and a
missing external input. Include positive and negative output examples with a
human review rubric. Offline tests prove fixture validity, expected inventory and
instruction delivery, not future model output quality. Optional model evaluations
retain the existing source hashes, traces, write restrictions and separate live
execution authority; no model call is required for this offline change.

Keep this as one cohesive implementation task: shared policy, its links and the
existing test/fixture seams change together. No new evaluator service, subjective
CLI rejection, rigid prose length limit, public command or runtime authority change.
One task review and integration are expected under the existing runner contract.

## Evaluation specimens

Use disposable native Git task-store fixtures and synthetic public identities.
Preserve seed scope, expected outcomes and forbidden-write controls. Cover native
and portable entrypoints, repository-supported engineering decisions, repairable
local fixtures, unavailable external qualification affecting only one independent
outcome, owner-only destructive scope and material builder findings resolved into
the saved contract. Retain interview/stop/resume, no-write, source recovery and
later-execution authority cases.

Offline tests prove valid seeds and instruction/fixture mechanics, not model decisions,
compliance or fewer stalls. Actual evaluation requires traces, source hashes and
separate host/provider authority. No model provider is required to finish an offline
fixture change. Existing CLI, decision-closure, decomposition, discovery and specimen
tests own these regression seams; do not duplicate every CLI runtime test.

## Delivery and authority limits

Disclose branch-local persistence versus actual canonical-consumer inclusion/selection;
runtime activity and ownership remain unassessed unless observed. Return ready work
to the existing authorized coordinator outside standalone planning. Preserve settled
authorization, interview/stop/resume rules, explicit no-execution scopes and live gates.
Use current Docs Sync capability/prepare handling without installing, forcing conversion,
interrupting workers or repeatedly preparing unchanged inputs.

Source correction, local integration, publication, installed adoption and live recovery
are separate observations. No static test supplies model-adherence, production or
live-qualification proof. Preserve active owners and original recoveries.
