# Pi RPC qualification boundaries

This document defines required evidence, not a completed-task report. Current
architecture, setup, version pins and rollback belong in [the runtime guide](../pi-rpc.md).
Git history retains prior bounded test and smoke results; they are not a fresh
installed-fleet qualification.

## Offline evidence

Use isolated release-bound fixtures for SDK transport, process ownership, event
projection, settlement, cancellation, provider fallback, reviewer independence,
recovery reservation and engine/Git integration. SDK-backed tests with a fake Pi
peer prove that boundary, not real-model engineering or installed adoption.

Import isolation and canonical/public module identity must remain checked. Preserve
source-bound failure results: a timed-out engine fixture or failed force-conversion
cleanup is not a pass. No optional dependency skip qualifies the skipped case.
Installation into a private dependency environment is not runner activation.

## Installed Pi, offline provider

A real executable with isolated HOME/resources and a deterministic fake provider
can qualify the executable/SDK contract, native events, session resume and independent
review context. It proves neither credentials nor real-model engine closure. Match
source, interpreter, SDK, executable and fixture inputs before reusing results.

## Remaining delivery gates

- Required independent review and merged-tree checks remain before source acceptance.
- Installed interrupted-attempt recovery and real engine closure need a single
  explicitly owned runner and separate live authority. Preserve paused jobs; no
  fleet restart or adoption is inferred.
- Matched engineering tasks, quality/check coverage, complete usage and billing
  provenance are needed before throughput, token or dollar comparisons. Missing
  totals stay unknown. A cold fixture is not a production latency distribution.
- Automatic steering stays off until its production control channel and intervention
  policy are separately qualified. Transport support alone supplies no such grant.
- Parent birth identity, pidfd and descendant cleanup do not provide hostile-process
  containment. Preserve SIGKILL/kernel limitations; stronger isolation needs its own
  delegated-cgroup qualification.

Model smoke results never substitute for installed-fleet acceptance, crash recovery,
complex coding quality, real-provider accounting or another task's acceptance.
No model, service, credential, installation or publication operation follows from
reading or updating these requirements.
