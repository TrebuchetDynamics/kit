# Autowork

A native Paseo workspace for an existing Autowork installation on a Linux workstation. Inspect runners, task contracts, goals, verification provenance, owner questions, logs and the scorecard from one selected host. Use the workspace panel, Command Center or `aw-*` composer commands to open the relevant view without creating a new coding-agent provider.

Paseo 0.13.x, 0.14.x or 0.15.x and Autowork prepare API 4 are required. By default all operations are read-only. A daemon-side policy file (`~/.config/autowork/policy.json` or `PASEO_AUTOWORK_CONFIG`) grants planning, owner answers, every task and goal edit, a tasks-only commit, runner controls (start, pause, resume, stop, restart, remove, update) and maintenance (model, clear-held, attention). A Settings screen shows the effective grants. Every mutation needs explicit confirmation and existing Autowork validation; no task, live-operation or publication authority is invented by the UI.

Planning uses Autowork's existing controller in plugin-owned sessions, in plan, discuss or investigate mode. Proposals remain unaccepted before Review and Apply. Worker/reviewer processes and Paseo-created Pi sessions are never attached or taken over. Disabling the plugin cancels only its own planning turns and retains upstream histories and work.

A change watch refreshes open views within seconds of a task, Git or runner-state change. The implementation has passed native-component fixtures, the official compiler, an isolated real Paseo plugin-runtime load test, a live local-daemon load and a server-side exercise against the live fleet. Physical Android/Desktop UI and real planning/service-control qualification through the app remain pending. Missing runtime or delivery provenance is displayed as unknown. No external telemetry or additional listening service is used.
