# Design

## Current scope

Kit supplies planning and repository-workflow skills. GitHub Issues own executable
work and Orbi owns delivery. Orbi remains paused and live-unqualified.

Current product contracts live in [the product specification](docs/project.md).
Use [GitHub-native delivery](docs/github-native.md) for the support boundary,
publication, ownership and qualification gates. Paseo remains an agent host, not
a Kit executor dashboard.

## Presentation principles

Show evidence and useful actions before decoration. Keep status, provenance,
identity and freshness visible. Distinguish loading, valid empty, unavailable and
stale observations. Process liveness is not implementation progress; missing
observations are not success. Keep keyboard access, readable labels and explicit
read-only boundaries. Documentation and registration checks are not visual,
physical-client or live-delivery qualification.

## Retained requirements

The [original terminal design and acceptance requirements](https://github.com/TrebuchetDynamics/kit/blob/ecc6061d7768dbe9286c6ca09ab403744b93ec1e/DESIGN.md)
and [interface qualification requirements](https://github.com/TrebuchetDynamics/kit/blob/ecc6061d7768dbe9286c6ca09ab403744b93ec1e/docs/plans/tui-responsiveness.md)
are immutable migration evidence, not current implementation instructions.
Reconcile still-required outcomes into GitHub Issues with their original evidence
and human/live gates. Removal does not satisfy unresolved SSH transport,
assistive-technology, physical-client or model qualification. Preserve existing
captures, attempts, worktrees and recovery state; do not revive an executor to
reproduce historical checks.
