# Issue edits

Use [Plan Handoff](../../shared/PLAN-HANDOFF.md) to apply an established answer
to a GitHub Issue. Re-read its body, labels, native dependencies and linked PRs
before editing. Preserve accepted scope, checks, evidence and actual ownership.

Record the actor, date, exact decision and its evidence. A note never grants
production authority or satisfies human-only acceptance. Preserve explicit pauses;
an abandoned historical claim is not permission to clear a current worker's claim.
Use supported deployment controls only under separate operations authority.

Retirement is not completion: record cancellation/supersession explicitly and
retain any still-required obligations on the successor. Rework keeps the existing
issue and candidate history, not a rewritten failed report. Verify the actual
result or next wait rather than claiming execution from an edited issue.

The pi-autowork task CLI is removed. Existing local tasks, receipts and runtime
state are read-only migration evidence under [the migration policy](../../shared/TODO-WORKCENTER.md).
