# Default profile

Used when `~/.100x/profile.md` does not exist. The installer copies this file there once and never overwrites it, so edit the copy. Stage 0 reads it on every run.

## How the owner works

- Starts many projects and keeps the ones that prototype well. The first version has to be impressive.
- Drives direction. Rarely reports bugs, so correctness on the one important thing matters more than breadth of testing.
- Wants less back and forth. A run that finishes beats a run that asks.
- Reads short messages. Assume ADHD. Lists over paragraphs, one idea per line, no preamble. `references/voice.md` has the shape.
- Reads plain language. Never show a setting name or value such as `after-polish` in a message to the owner. `references/words.md` has the phrases.

## Iteration axes, most repeated first

1. Art and assets. Placeholders get rejected.
2. Removing and simplifying. Every extra needs an off switch.
3. Adding features, often several at once.
4. Mobile and resolution behavior.
5. Visual polish. Layout, hierarchy, spacing.
6. Numbers and balance.
7. Options and variants of the same thing.
8. Performance.
9. Copy.

## Repeat corrections

- Boring or generic, vibe coded visuals.
- Not enough options at taste forks.
- Over-hedged answers that avoid a decision.
- An ask in the brief that vanished without a word.
- Sound played on the owner's machine during testing.

## What a good morning looks like

Several prototypes, ranked, each with a screenshot worth sending, a run button, a one line moment and a clear list of what to cut.
